# ILCE-7RM3 (A7R3) 3.10 固件 10-bit 录制静态闭环分析报告

- **样本**：`av-cam.bin` (`SHA-256: 35e3ff3f931fa725928ab8c7493d4b9842e1f90c3fa7b90ab4e23274256dd800`) 及 `nflasha15` (`libmpr.so`, `libObj.so` 等全分区文件)
- **地址约定**：`av-cam.bin` 为文件内偏移（小端 Thumb-2，运行期基址 `0x635c6000`）；`libmpr.so` 为 ELF 虚拟地址。

---

## 1. 核心缺口闭环：谁写入了 REC 描述的 `+0x36`？

**结论：全固件没有任何指令向 `SyncYCOut` 的 `REC` 通道描述 `+0x36`（及任何送往视频编码器的 `YC` 记录 `+0x36`）写入非零值。编码器参数 `+0x50` 在原厂固件所有录像模式下恒为 `0`（8-bit）。**

### 1.1 `SyncYCOut` 通道表 `0xd8e618` 全固件引用穷举
对 18,268,416 字节 `av-cam.bin` 执行全盘 PIC 引用（`ldr rX, [pc, #imm]` + `add rX, pc`）与绝对指针（`0x635c6000 + offset`）扫描：
- 指向 `0xd8e618`（4 通道 × `0x3c` 字节，`REC = 1` 位于 `0xd8e654`，其 `+0x36` 位于 `0xd8e68a`）的引用**全文件共计 26 处 PIC 引用、0 处绝对指针引用**，全部位于 `SyncYCOut.cpp`（`0x3804c0`–`0x381bf2`）。
- 通道配置函数 `0x3803dc` 中对 `0xd8e618 + r5 * 0x3c` 的全部写入指令如下：
  - `0x3804c0`–`0x3804dc`（及禁用分支 `0x380a30`–`0x380a3e`）：写 `+0x00` (1B)、`+0x04` (4B)、`+0x08` (2B)、`+0x0c` (4B)
  - `0x3804e8`–`0x3805a6`：写 `+0x10` (1B)、`+0x11` (1B)、`+0x13` (1B)、`+0x14..+0x2a` (12 个半字窗口/尺寸参数)、以及 **`+0x38` (`0x38051e: strh r0, [r6, #0x38]`)**
  - `0x3805b0`–`0x3805ba`：写 `+0x2c` (1B = 0)、`+0x2d` (1B = 0)
  - `0x3805d0`–`0x38064a`：写 `+0x2e` (1B，由参数 `+0x38` 的 `0..5` 映射为 `2,0,1,6,3,4`)
  - `0x38065a` / `0x38066a`：写 `+0x2f` (1B，归一化为 `0/1`)
  - `0x380682` / `0x380692`：写 `+0x33` (1B，归一化为 `0/1`)
  - `0x3806a8`–`0x3806d4`：写 `+0x30` (1B)、`+0x31` (1B)、`+0x32` (1B)、以及 **`+0x34` (`0x3806b2: strh r0, [r3, #0x4]`，写入半字 `0x0040`，覆盖 `+0x34..+0x35`)**
- **关键事实**：`+0x36..+0x37` 被完全跳过，没有任何写入指令；`0x38130c`–`0x381bf2` 中的其余 PIC 引用全部为只读（状态检查、日志打印，以及 `0x3813f8: bl 0x7b042e` 整块 `0x3c` 字节打包发送）。因此 `0xd8e68a` 恒保持初值 `0x00`。

### 1.2 全固件 `Bundle_SetYC` (`0x7b0cec`) 生产者穷举
`enc/sfmc_enc_input_yc.cpp` 在 `0x64883e` 调用 `0x7b0ce0` 提取 `YC` 描述并拷入对象 `+0x74..+0xaf`（该区域在对象初始化 `0x66f1b0` / `0x66f21a` 时经 `memset(this+0x70, 0, 0xd0)` 清零；`0x66f34e` 后续仅写 `+0x70/+0xb0/+0xd0/+0x130..+0x13c`，不触碰 `+0xaa` 即 `0x74+0x36`）。

全盘扫描对应的打包写入函数 `0x7b0cec`，**整个 `av-cam.bin` 仅有 5 处调用者**：
1. `0x381406`（`SyncYCOut.cpp`）：主录像 `REC=1` / `PROXY=2` 发送端，拷入 `0xd8e618 + r5*0x3c`，`+0x36` 恒为 `0`。
2. `0x59f40`：经构造函数 `0x4e62e4`（内部 `0x4e62fe` 执行 `memset(this+0x14, 0, 0x3c)` 清零），仅调 setter 至 `0x7b059c`（`+0x2e`），`+0x36` 恒为 `0`。
3. `0x14e548`：经 `0x4e62e4` 清零，仅调 setter 至 `0x7b05d8`（`+0x34`），`+0x36` 恒为 `0`。
   - **旁证**：`YC` 记录类的成员访问器（`0x7b0472`–`0x7b05e0`）最后一个 setter 即 `0x7b05d8`（`strh r1, [r0, #0x48]`，对应 payload `+0x34`），**该 C++ 类甚至没有为 payload `+0x36`（`this+0x4a`）生成任何 setter 方法**。
4. `0x34d5c0`（`CaptureUtilityStdYc.cpp`）：拍照/抓图工具路径（非录像主流），栈构造同样只写到 `sp+0x198`（`+0x34`）。
5. `0x6548dc`（`sfmc_dec_yc_pin`）：解码回放侧，非录制编码。

### 1.3 `CODEC V` 编码参数 `+0x50` 唯一构造链确认
- `SetupMovieEnc` (`0xb78dc`) 全固件仅有唯一调用者 `0x66cab8`；
- 参数日志函数 `0xb6090` 与提交函数 `0xb7814` 均仅在 `0xb7a38` / `0xb7a40` 被调用一次；
- 子结构填充函数 `0xb59b8` 仅在 `0xb7a02` 与 `0xb7f08` 被调用，其 `0xb5a00: ldrb.w r3, [r1, #0x36]` 读取上述恒为 `0` 的字节并向子结构 `+0x14`（即总参数 `+0x50`）写入 `0`，后续 `0xb5980` -> `0xb5864` 仅写 `+0x20..+0x40`，不覆盖 `+0x14`。

## 2. Linux 侧 `libmpr.so` 与 `libObj.so` 全盘核查

对 `firmware.tar` 内 `0700_part_image/dev/nflasha15` 整个根文件系统镜像做全量扫描：
1. **`MprIf::SetRecVideoBitDepth` 为未引用的平台 SDK 残留代码**：
   - `_ZN5MprIf19SetRecVideoBitDepthEPNS_14VBitdepthParamEm` (`0x88558c`)、`_ZN5FeaIf19SetRecVideoBitDepth...` (`0x53a53c`)、`_ZN7FeaCore19SetRecVideoBitDepth...` (`0x521af4`) 在整个 `nflasha15` 镜像中各自仅出现 **1 次**（即 `libmpr.so` 自身的符号定义），没有任何其他可执行文件、库或 `/scenario/*.so` 导入。
   - 在 `libmpr.so` 内部，`0x88558c` 同样为 **0 次直接调用、0 处重定位、0 处虚表引用**。
2. **`libObj.so` 无位深分支**：
   - 19.5 MB 的 `libObj.so` 全文件不含 `BitDepth` 或 `10bit` 字符串；`SLOG3` 相关配置项仅涉及最低 ISO 限制（如 `PARAMID_EXC_CONF_PP_MIN_ISO_SLOG3_MOVIE_MODE`），不存在根据 S-Log2 / S-Log3 切换位深的逻辑。

## 3. `0xd8d82c` / `0xd8d8e8` 补充收敛

- `0xd8d82c` 在整个 `av-cam.bin` 中仅有 3 处 PIC 引用（`0x377f28`、`0x37c9e4`、`0x37ca1c`）。
- 在 `0x37ca1c`–`0x37ca24` 处，固件直接执行 `memcpy(0xd8d82c, 0xd8d8e8, 0xbc)`，说明 `0xd8d82c` 只是 `0xd8d8e8` 的 `0xbc` 字节备份快照，后续若需追踪 `+0x80`（YUV 格式枚举来源），只需追踪 `0xd8d8e8` 一处即可。
